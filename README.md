# AI Advent Challenge #9 — Week 02, Day 08

**Задание:** работа с токенами — считать токены текущего запроса, всей истории и ответа; сравнить короткий диалог, длинный и превышающий лимит модели; показать, как растёт стоимость по мере диалога и что ломается при переполнении.

Trigger Helper (day08): эвристическая оценка токенов + фактический usage от API. **Preflight-лимит контекста**: запрос, который не влезает в окно модели, отклоняется HTTP 413 **до** вызова LLM (0 ₽) с breakdown system/history/user. Кнопка **«Сжать»**: старая история сворачивается в одну system-сводку дешёвой моделью (последние 4 сообщения — дословно), окно освобождается, диалог продолжается. Плюс холостой замер экономики сжатия: A/B с учётом кэша провайдера и точкой окупаемости.

**Live demo:** http://91.188.212.10/ · **Tag:** [`week02-day08`](https://github.com/kosvitko/trigger-helper-advent/tree/week02-day08)

Модель в демо — дефолтная дешёвая (DeepSeek chat), одна, без ×3. Реальное окно модели — 128K, поэтому для демонстрации переполнения оно форсируется env-переменной `DEMO_CONTEXT_LIMIT` (окно промпта в токенах).

## Demo на видео (85s)

| | |
|:--|:--|
| Рост | диалог при `DEMO_CONTEXT_LIMIT=1000`: панель токенов, спарклайн prompt-токенов, полоса к лимиту жёлтеет, кумулятив ₽ растёт |
| Переполнение | очередной вопрос → **413 preflight до LLM (0 ₽)**: баннер «Запрос ≈1227 ток — не влезает в контекст (1000 ток, история: tail)» + breakdown, полоса красная |
| Сжатие | «Сжать» → бейдж **«сжатие ~1.0k → ~583 (₽0.04)»**, старая история стала одной сводкой, полоса упала |
| Восстановление | тот же вопрос → агент снова отвечает, диалог продолжается |
| Экономика | «Измерить экономию» → карточка: ₽ за вопрос до и после сжатия (холодный/тёплый кэш) и точка окупаемости |

## Что где реализовано

| Требование | Где |
|:-----------|:----|
| Оценка токенов | `server/src/services/agent/token-estimate.ts` — эвристика (кириллица ~2.5 симв/ток, латиница ~4), breakdown запроса, тред-тоталы |
| Лимиты моделей | `server/src/services/model-cost-tier.ts` — окно по семействам (128K/200K/1M); `DEMO_CONTEXT_LIMIT` форсит окно промпта для демо |
| Подсчёт за запрос | `POST /api/agent/run` — estimate + фактический usage (prompt/completion/кэш) и ₽ в каждом ответе и бейджах |
| Серия по истории | `GET /api/instances/:id/agents/:aid/tokens` — prompt/completion/₽/кумулятив по сообщениям, 0 LLM-вызовов |
| Переполнение | `server/src/services/agent/llm-agent.ts` — preflight `estimate > limit` → `ContextLimitError` → HTTP 413 с breakdown; отказ до траты запроса |
| Сжатие | `POST .../compress` — старая история → одна system-сводка (≤120 слов, дешёвая модель, keepLast=4 дословно); `saved_tokens` пишется в снапшот (день07) — экономия окна переживает рестарт |
| Экономика сжатия | `POST .../compress/probe` — 4 холостых вызова (было → сжатие → стало cold/warm), тред не меняется, ответы не выводятся; в UI — ₽ за вопрос до/после и точка окупаемости |
| UI | `server/public/index.html` — панель токенов («~X ток в окне · Y ток израсходовано API · ₽»), спарклайн, полоса к лимиту (warn/over), баннер 413, кнопки «Сжать» и «Измерить экономию» |

Нюанс, который показывает замер: при агрессивном кэше провайдера стабильный префикс (system + старая история) идёт по hit-цене, поэтому на коротких тредах сжатие деньгами не окупается — его выгода в освобождении окна (диалог продолжается вместо 413), а денежная экономия проявляется на длинных хвостах. Карточка «Измерить экономию» показывает это честно — с холодным и тёплым кэшем и точкой окупаемости в вопросах.

## Быстрый старт

```bash
git clone https://github.com/kosvitko/trigger-helper-advent.git
cd trigger-helper-advent
git checkout week02-day08
cp .env.example .env   # DEEPSEEK_API_KEY=...
npm install
npm run dev            # http://127.0.0.1:3000 — Agent UI

# демонстрация переполнения: малое окно промпта
DEMO_CONTEXT_LIMIT=1000 npm run dev
```

## Demo через API

```bash
# инстанс + агент
curl -X POST http://127.0.0.1:3000/api/instances -H "Content-Type: application/json" -d '{"seedPresetIds":["care"]}'

# пара вопросов → история растёт
curl -X POST http://127.0.0.1:3000/api/agent/run -H "Content-Type: application/json" \
  -d '{"instanceId":"<iid>","agentId":"<aid>","input":"Шея каменная — какую точку проверить?"}'

# токены треда серией (0 LLM-вызовов)
curl http://127.0.0.1:3000/api/instances/<iid>/agents/<aid>/tokens

# переполнение: с DEMO_CONTEXT_LIMIT=1000 на длинной истории → 413 + breakdown
# сжатие истории в сводку
curl -X POST http://127.0.0.1:3000/api/instances/<iid>/agents/<aid>/compress \
  -H "Content-Type: application/json" -d '{"keepLast":4}'

# холостой замер экономики сжатия (4 вызова, тред не меняется)
curl -X POST http://127.0.0.1:3000/api/instances/<iid>/agents/<aid>/compress/probe \
  -H "Content-Type: application/json" -d '{"keepLast":4}'
```

## Структура репозитория

```
server/   API (agents / instances / run / messages / tokens / compress) + Agent UI
shared/   Zod-схемы: инстансы, агенты, сообщения, compress
data/     точки для grounded-режима
var/      снапшот контекста (agent-state.json) — вне git
```

Ключ API только в env на сервере, не в клиенте и не в git.

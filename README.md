# AI Advent Challenge #9 — Week 05, Day 21

**Задание:** набор документов (README/статьи/код/pdf → текст; ≥20–30 страниц или эквивалент) → пайплайн индексации: разбиение на чанки → генерация эмбеддингов → сохранение индекса (FAISS/SQLite/JSON). Усиление: метаданные каждого чанка (source, title/file, section, chunk_id) + минимум 2 стратегии chunking (по фиксированному размеру vs по структуре) и сравнить их. Результат: локальный индекс с эмбеддингами + метаданные + сравнение стратегий. Формат: видео + код.

Trigger Helper (day21): **локальный RAG-индекс по документации проекта** — 75 файлов (README + `docs/`, ~826 КБ ≈ 300+ страниц) → **две стратегии чанкинга** → **локальные эмбеддинги** (`Xenova/multilingual-e5-small`, 384-dim, ONNX, префиксы `query:`/`passage:` — ₽0, без ключей и внешних API) → JSON-индексы в `data/rag/` с метаданными каждого чанка (`chunk_id`, `source`, `file`, `title`, `section`). **Fixed** — окна ~450 токенов (кап e5 512) с перекрытием 15%, рез по абзацам; **structured** — разрез по заголовкам секций `#…###`, markdown-таблицы режутся по горизонтальным границам строк, каждое продолжение начинается с шапки таблицы, продолжения секций несут якорь `[путь секции]`. Чанки упаковываются в токен-бюджет — таблицы не рассыпаются на однострочные куски. Поиск: `GET /api/rag/search` (косинус по нормированным векторам, топ-k) + `GET /api/rag/stats` (счётчики, метрики границ, сравнение стратегий); в UI — блок-история пайплайна и карточки поиска прямо в чате (score · source › section · excerpt · chunk_id, клик — чанк целиком). В видео — три руки сравнения: **fixed / structured / без RAG** (тот же вопрос агенту без заземления на доку).

**Качество резки и метрики границ:** чанк считается «оборванным внутри блока» (списки/таблицы) или «внутри предложения» (строгая) — в финальном индексе 6.3–6.8% / 4.0–6.3% соответственно. Сравнение на 17 пробах с честным ground truth (9 уникальных канонических файлов + 8 multi-label групп «proposals+design»): **fixed — hit@1 0.59 / hit@5 0.94 / MRR@10 0.72; structured — 0.59 / 0.82 / 0.68.**

## Выводы

для корректной работы раг нужно грамотно выполнить: подбор базы (похожие), нарезку на чанки в соответствии с контентом, выбор модели для эмбеддингов. Так как на выбранном примере лучший результат показал фиксед подход. хотя структурированный выглядит логично. 
Есть ощущение, что нарезка на фиксированные чанки включила в себя больше релевантной информации, чем структурированная. В любом случае требуется вдумчивый выбор и тесты при внедрении в свою систему

## Что где реализовано

| Требование | Где |
|:-----------|:----|
| Корпус документов | `services/rag/corpus.ts` — README + `docs/**/*.md` без private/_archive, UTF-8, нормализация CRLF |
| Чанкинг, 2 стратегии | `services/rag/chunking.ts` — токен-бюджет ~450 первичен; fixed: окна + overlap 15%, рез по абзацам; structured: ATX-секции `#…###` + якорь пути в продолжениях; oversized: предложения/строки таблиц; таблицы — по границам строк с повторением шапки |
| Эмбеддинги | `services/rag/embeddings.ts` — `@huggingface/transformers` (ONNX), `Xenova/multilingual-e5-small` q8, mean-pooling + normalize, префиксы `query:`/`passage:`, кэш весов `var/hf-cache` |
| Сохранение индекса | `services/rag/store.ts` + `scripts/build-rag-index.ts` (`npm run rag:index`) — `data/rag/rag-index-{fixed,structured}.json` + `compare-stats.json`, атомарная запись tmp+rename |
| Метаданные чанка | `chunk_id` (`<strategy>:<source>:<idx>`), `source`, `file`, `title`, `section`, `position`, `text`, `vector` |
| API поиска | `routes/rag.ts` — `GET /api/rag/search?q&strategy&k&full` (400 zod / 503 degrade-not-crash), `GET /api/rag/stats` |
| UI | `server/public/index.html` — блок-история пайплайна (4 шага) + карточки поиска в чате, `full=1` — чанк целиком |
| Сравнение стратегий | `compare-stats.json` — hit@1/hit@5/MRR@10 на 17 пробах (9 уникальных файлов + 8 multi-label групп), метрики границ чанков |

## Быстрый старт

```bash
git clone https://github.com/kosvitko/trigger-helper-advent.git
cd trigger-helper-advent
git checkout week05-day21
cp .env.example .env   # ключи не нужны: эмбеддинги считаются локально
npm install
npm run rag:index      # корпус → чанки → эмбеддинги → data/rag/ + сравнение
npm run dev            # http://127.0.0.1:3000 — блок «RAG» в правой панели
```

## Demo через API

```bash
# счётчики индексов, метрики границ, сравнение стратегий
curl http://127.0.0.1:3000/api/rag/stats

# поиск по базе знаний (top-3, fixed; полный текст чанка — &full=1)
curl "http://127.0.0.1:3000/api/rag/search?q=%D0%B1%D0%BE%D0%BB%D1%8C%20%D0%B2%20%D1%88%D0%B5%D0%B5&strategy=fixed&k=3&full=1"

# та же проба на structured — выдача отличается
curl "http://127.0.0.1:3000/api/rag/search?q=%D0%B1%D0%BE%D0%BB%D1%8C%20%D0%B2%20%D1%88%D0%B5%D0%B5&strategy=structured&k=3"
```

Деградация (дизайн-контракт): индекс отсутствует/повреждён/рассинхрон модели → `503 {error}` и сервер живёт (degrade-not-crash); блок «RAG» в UI скрывается.

# AI Advent Challenge #9 — Week 05, Day 23

**Задание:** добавить второй этап после поиска — reranker или фильтр релевантности (порог similarity / отдельная модель / heuristic). Настроить порог отсечения нерелевантных результатов и топ-K до/после фильтрации. Сравнить качество без фильтра/rewriting и с фильтром. Результат: улучшенный RAG — фильтрация/реранкинг + query rewrite + сравнение режимов. Формат: видео + код.

Trigger Helper (day23): **второй этап — локальный кросс-энкодер** `BAAI/bge-reranker-v2-m3` (ONNX q8, ~544 МиБ, мультиязычный вкл. русский) + **multi-query rewrite**: один дешёвый вызов DeepSeek переформулирует вопрос читателя в 2–3 поисковых запроса на языке базы (названия мышц, симптомы), поиск идёт по всем вариантам **вместе с исходным вопросом** (union по максимуму — оригинал вытеснить нельзя), варианты кормят только поиск — ответ пишется по исходному вопросу. Этапы включаются флагами в том же `POST /api/rag/ask`: **arms `base` (как day22) / `rerank` / `rewrite` / `full`** — сравнение на одних и тех же 10 контрольных вопросах.

Порог отсечения не берётся с потолка: скрипт `npm run rag:tune` измеряет на 12 пробах корпуса распределение скоров реранкера (ожидаемые чанки vs дистракторы) и фиксирует порог в коммит-артефакте `data/rag/tune-rerank.json`. Замер показал, что глобального зазора у кросс-энкодера нет (масштаб скоров плавает от запроса к запросу) → принята **относительная маржа** top1 − 0.05. Топ-K виден в каждом ответе: `топ: 220 → kept → injected`.

**Матрица (10 контрольных вопросов):**

| arm | PASS | mean | токены | время* |
|:----|:--:|:--:|:--:|:--:|
| base (day22) | 7/10 | 0.83 | ~3 778 | 4.0 s |
| rerank (порог) | 5/10 | 0.78 | ~1 450 | 56.8 s |
| rewrite | 5/10 | 0.80 | ~3 869 | 4.5 s |
| **full (rerank + rewrite)** | **8/10** | **0.92** | **~1 895** | 54.3 s |
| *анкер day22 (без RAG)* | *5/10* | *0.75* | *~10 070* | *4.2 s* |

\* время — локальная машина (кросс-энкодер 568M на CPU); токены DeepSeek.

## Выводы

реранкинг требует отдельной оптимизации, подбора стратегии на корпусе данных. Может дать существенную экономию, но за счет значительного увеличения (в зависимости от локальной машины и модели) времени ответа. В текущем примере: 2х сокращение бюджета за 10-20х увеличения задержки. При этом качество ответов пока что падает (режим дешево и менее качественно). Более качественный режим доступен за тот же бюджет времени при небольшом увеличении бюджета токенов.
Как обычно - нужно тщательно исследовать работу метода на конкретных данных в конкретной области.

## Что где реализовано

| Требование | Где |
|:-----------|:----|
| Второй этап — reranker (отдельная модель) | `services/rag/rerank.ts` — кросс-энкодер `BGLAW/bge-reranker-v2-m3-onnx-defaulttask` (q8, батч ≤8, sigmoid(logit)); ручной `AutoTokenizer` + `AutoModelForSequenceClassification` (pipeline-text-classification даёт softmax≈1 — не использовать) |
| Порог отсечения | tune-артефакт `data/rag/tune-rerank.json` — `scripts/tune-rerank.ts` (`npm run rag:tune`): 12 проб корпуса (тест-сет не участвует), распределение ожидаемые/дистракторы, порог relative-margin top1 − 0.05 (глобального зазора нет); ранг-1 никогда не отсекается |
| Топ-K до и после фильтрации | в каждом ответе: `meta.poolRanked → meta.keptAfterFilter → meta.injectedCount` (и в строках eval-артефакта) |
| Query rewrite | `services/rag/rewrite.ts` — 1 вызов deepseek-chat (jsonMode, temp 0): 2–3 варианта запроса; union по максимуму в `store.rankByQueries`; фолбэк на исходный вопрос при любом сбое; варианты — только в поиск |
| Сравнение режимов | флаги `rerank`/`rewrite` в `POST /api/rag/ask` → arms base/rerank/rewrite/full; `scripts/eval-rag-answer.ts` (`npm run rag:eval`) — матрица 4×10 + анкер day22, `data/rag/eval-answers.json` (v2: stage, rewrite_tokens) |
| UI | `server/public/index.html` — селектор этапа в ask-строке, eval-карточка v2, в карточке ответа строка «топ: 220 → kept → injected» + цена (токены · время · реранк · rewrite) |
| Деградация | сбой загрузки/инференса реранкера или `RAG_RERANK_ENABLED=0` → `503` только для rerank/full arms (base/rewrite работают); артефакт tune бит/отсутствует → тот же 503 |

## Быстрый старт

```bash
git clone https://github.com/kosvitko/trigger-helper-advent.git
cd trigger-helper-advent
git checkout week05-day23
cp .env.example .env        # нужен только DEEPSEEK_API_KEY (эмбеддинги и реранкер локальные)
npm install
npm run rag:index           # корпус карточек → чанки → эмбеддинги → data/rag/ (уже в репо)
npm run rag:tune            # ВНИМАНИЕ: первый прогон качает ~544 МиБ весов кросс-энкодера
npm run dev                 # http://127.0.0.1:3000 — блок «RAG», селектор этапа

# матрица 4 arms × 10 контрольных вопросов (сервер остановить: ledger — единый писатель)
npm run rag:eval
```

На хостах с <2 ГБ свободной RAM поставьте `RAG_RERANK_ENABLED=0` — rerank/full arms будут отвечать `503` до загрузки модели, base/rewrite продолжат работать.

## Demo через API

```bash
# base — как day22 (structured k=12)
curl -X POST http://127.0.0.1:3000/api/rag/ask \
  -H "Content-Type: application/json" \
  -d '{"q":"мурашки по верху предплечья — от какой мышцы","mode":"rag"}'

# rewrite — multi-query union (варианты видны в meta.rewrite)
curl -X POST http://127.0.0.1:3000/api/rag/ask \
  -H "Content-Type: application/json" \
  -d '{"q":"мурашки по верху предплечья — от какой мышцы","mode":"rag","rewrite":true}'

# full — реранк + порог + rewrite (мета: топ-K до/после, латентность реранка)
curl -X POST http://127.0.0.1:3000/api/rag/ask \
  -H "Content-Type: application/json" \
  -d '{"q":"мурашки по верху предплечья — от какой мышцы","mode":"rag","rerank":true,"rewrite":true}'

# артефакты: порог — data/rag/tune-rerank.json, матрица — /api/rag/eval
curl http://127.0.0.1:3000/api/rag/eval
```

Деградация (дизайн-контракт): индекс отсутствует/повреждён или реранкер недоступен на хосте → `503 {error}` только для rerank/full arms (base/rewrite живут); сбой LLM → `502`; rewrite-сбой → тихий фолбэк на исходный вопрос; исчерпан дневной бюджет → `429`.

# AI Advent Challenge #9 — Week 07, Day 32

**Trigger Helper** — продуктовый SPA самопомощи по триггерным точкам (Svelte 5 + Fastify). День 32 — **автоматическое AI-ревью кода**: локальный пайплайн, где ассистент анализирует коммит/PR — получает diff и изменённые файлы, использует RAG по документации **и коду** проекта, выдаёт ревью (потенциальные баги / архитектурные проблемы / рекомендации) с вердиктом `approved / changes_requested`. Строгий режим: **pre-push git-хук** — без approve пуш не проходит.

## Demo на видео

1. **`npm run review:commit`** — ревью последнего коммита до пуша: вердикт, рубрики, источники RAG.
2. **Ветка с подсаженным багом** → `git push` → pre-push хук сам запускает ревью → `changes_requested` → **ПУШ ЗАБЛОКИРОВАН**.
3. **Фикс-коммит** → `git push` → `approved` → пуш прошёл.
4. **`npm run review:pr -- 1`** — тот же движок на реальном PR из GitHub API (этот репозиторий, без токена).

## Выводы

отличная механика. Осталось понять, имеет ли смысл такое ревью при работе уже с агентами. Т.к., например, в существующем процессе предусмотрен шаг рефакторинга (на волну, например, изменений, когда все кросс-чекается). а во время выполнения задачи вроде как агенты добиваются, чтобы не было дефектов (проходили тесты и т.п.). И неясно, что бы смог сделать ревьювер в таком ключе. Т.к. код как бы итеративно обрабатывается агентами-разработки. Предыдущая история (процесс с активным шагом ревью кода) показала, что за все время было выловлено лишь несколько минорных несоответствий. И пока непонятно, будет ли целесообразно ревьювить агентский код при условии того, что в процессе предусмотрен запуск тестов до грин состояния.

## Что где реализовано

| Пункт задания | Где |
|:---|:---|
| Пайплайн запускается на PR | `npm run review:pr -- <N>` — GitHub REST API; `review:commit` / `review:push` — локально |
| Ассистент получает diff и файлы | `git diff` + name-status (диапазон / PR), капы 60 файлов / 60k символов |
| RAG (документация + код) | корпус `data/project-rag/` — README, docs, схемы, `server/src/**`, `client/src/**` (120 файлов / 856 чанков); `npm run rag:index:project` |
| Баги / архитектура / рекомендации | ядро `server/src/services/review.ts` — DeepSeek JSON-режим, вердикт + 3 рубрики + источники |
| Автозапуск (без ручной команды) | `.githooks/pre-push` (strict: нет approve → нет пуша; обход `REVIEW_SKIP=1` / `--no-verify`); включение: `npm run hooks:install` |

## Быстрый старт

```bash
npm install
npm run build

# индекс проекта «документация + код» (один раз / после смены корпуса)
npm run rag:index:project -w server

# включить strict pre-push ревью (один раз на клон)
npm run hooks:install

cd server && npm run dev   # не обязателен для ревью: CLI работает напрямую
```

Ревью: `npm run review:commit -w server` · `npm run review:pr -- 1 -w server` (демо-PR этого репозитория). Далее обычный `git push` — хук сам ревьюит пушимые коммиты.

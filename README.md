# AI Advent Challenge #9 — Week 07, Day 34

**Trigger Helper** — продуктовый SPA самопомощи по триггерным точкам (Svelte 5 + Fastify). День 34 — **ассистент для работы с файлами проекта**: кнопка «+ Файлы» открывает чат, куда разработчик ставит задачу целью — «найди, где используется X», «оформи справочником и сохрани», «добавь туда информацию про…». Ассистент сам ищет по живому коду (точный grep-поиск `repo_search`), читает нужные файлы и создаёт/обновляет артефакты в рабочем пространстве через `files_write` с unified diff; файлы репозитория — строго read-only (jail по каталогам, расширениям и размеру).

## Demo на видео

Одна реальная задача — карта использований под рефакторинг тулзов (четыре хода, живые формулировки без «промпт-инженерии»):

1. **Поиск:** «Собираюсь рефакторить тулзы репозитория. Найди, где используется dispatchRepoTool» → ассистент ищет по исходникам и отвечает картой `file:line`.
2. **Артефакт:** «Оформи это справочником и сохрани» → сам выбирает имя и путь (`var/files-workspace/reports/dispatchRepoTool-usage.md`), пишет файл, diff видно в трейсе.
3. **Изменение:** «Добавь туда информацию про то, как устроены jail и allowlist» → перечитывает артефакт, дополняет, diff.
4. **Повтор:** «Пересобери справочник начисто» → не «файл уже есть»: перечитал, сверил с исходниками, перезаписал.

Серверная рельса «просил артефакт — ход записал»: ход с намерением файла без записи дожимается одним re-prompt'ом; чтение и чистый поиск рельсой не трогаются.

## Выводы

тщательная настройка RAG (разные методики для кода и текста из-за характеристик контента) позволяет эффективно использовать недорогие модели для поиска и структурирования информации. Сам тулинг при этом может строго ограничивать как область видимости, так и учитывать какие-то дополнительные правила, убирать секреты и т.п.

## Что где реализовано

| Пункт задания | Где |
|:---|:---|
| Читать файлы проекта | `repo_read_file` / `repo_list_files` (in-process tools, дни 31+) |
| Искать по нескольким файлам | `repo_search` — подстрока без учёта регистра по allowlist-корням, выдача `path:line`, капы 50/4000 |
| Анализировать содержимое | tool-loop llm-agent (DeepSeek): карта использований, сверка артефакта с исходниками |
| Создавать/изменять файлы | `files_write` (`services/files-tools.ts`): jail `var/files-workspace/**`, .md/.json, ≤16k, атомарная запись tmp+rename, unified diff (LCS) на выходе |
| Задача целью, не «открой файл X» | пресет `files`: ассистент сам планирует поиск → чтение → артефакт; имена файлов не диктуются |
| Изменения сохраняются или diff | оба: файл на диске + diff в трейсе (new file / дополнение / пересборка) |
| Воспроизводимость | повторный запрос → перечитать + сверить + перезаписать; смоук 2/2 одной целью |
| Безопасность | живое репо read-only; deny `.env*`/`var`/`node_modules`/`.git`/private; секреты недоступны тулзам |

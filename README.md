# AI Advent Challenge #9 — Week 06, Day 29

**Trigger Helper** — продуктовый SPA самопомощи по триггерным точкам (Svelte 5 + Fastify). День 29 — **оптимизация локальной LLM под конкретную задачу** (RAG-ответы по базе триггерных точек): тюнинг-профиль параметров (temperature / max tokens / context window), промпт-шаблон под кейс и проба квантования — с честным A/B-сравнением «до / после» по качеству, скорости и потреблению ресурсов. Живое демо: https://trigger.ksvitkov.ru

## Demo на видео

1. **Настройки**: каталог локальных моделей Ollama с бейджами доступности (0.5B «доступна», 1.5B «доступна», 3B «не установлена»), выбор Qwen2.5 1.5B — чип композера «локальная · Qwen2.5 1.5B · RAG».
2. **Локальная ветка — два хода (чат A)**: «какая мышца отвечает за жевание?» — живой поиск по базе (тикер ⏱, фаза реранка) → генерация «● N ток» → ответ 2–4 предложения строго по карточке (RAG-промпт дня 29), чип «Источники 1», ₽0.00; затем «техника самомассажа» — внутриротовой приём из секции «Техника» карточки.
3. **Облачная ветка — те же два вопроса (чат B, дефолтная free)**: полный агентный цикл в трейсе (· поиск по базе → · черновик → · верификация цитат → Рельса-чек ✓), «Память задачи» заполняется («Цель: Узнать, какая мышца…»), развёрнутые ответы с «Источники 12 · цитаты 3/5». Контраст: локальная — короткий детерминированный контур (поиск → генерация), облачная — полный агентный.
4. **Сравнение переключением чатов** (~10 с на чат) — обе ленты с одними и теми же вопросами: короткие ответы ₽0 против развёрнутых с источниками.
5. **Терминал: `npm run local-llm:tune -- --report`** — таблица A/B трёх конфигураций (до = день 28 / после = профиль дня 29 / после + квант q5_k_m): заземление, длина ответа, p50 генерации, ток/с, prompt-токены, RAM, холодный старт.

Главный измеримый эффект тюнинга — **высокая стабильность ответов**: на дефолтных параметрах рантайма (темп 0.8) один и тот же вопрос давал ответы от 114 до 236 токенов между прогонами; профиль дня 29 (темп 0.2) практически устраняет разброс — в замерах повторы совпадали дословно (строгое повторение дала бы только температура 0). Попутно ускорен поиск: пул реранка 40 → 24 кандидата (~39 → ~29 с на CPU) без потери качества (все контрольные карточки в пуле с запасом).

## Что где реализовано

| Пункт задания | Где |
|:---|:---|
| Параметры: temperature | `server/src/services/local-llm.ts` — `LOCAL_LLM_TEMPERATURE = 0.2` (глобально для локальной ветки); замер A/B: разброс длины ответа между прогонами q05 114↔236 ток → 79↔88, повтор вопроса — идентичный текст |
| Параметры: max tokens | `LOCAL_LLM_NUM_PREDICT = 320` — потолок ответа «2–4 предложения», защита от разгонов при неограниченном дефолте рантайма |
| Параметры: context window | per-entry каталога `tuning {numCtx, ragPromptTokenBudget}`: 0.5b → {2048, 1000} (слабые хосты/прод), 1.5b/3b → {4096, 2000}; бюджет retrieved-контекста передаётся в сборку (`localRagAssemble`) |
| Prompt-шаблон под кейс | `LOCAL_LLM_RAG_PROMPT` — включается при наличии retrieved-контекста: отвечать ТОЛЬКО по блоку «ДАННЫЕ», 2–4 предложения, мышца/техника/симптомы конкретно, нет данных — сказать прямо |
| Квантование | q8_0 (веса ≈1,65 ГБ) — отклонён по RAM машины; опробован q5_k_m (GGUF + `ollama create`): строка таблицы A/B с числами; прироста качества нет — в каталог продукта не добавлен (решение по артефакту, не по вкусу) |
| Сравнение до/после: качество, скорость, ресурсы | `server/src/scripts/tune-local-llm.ts` + `npm run local-llm:tune`: 8 контрольных × {до, после, после+квант} × 2 прогона; retrieval один на вопрос (rank + реранк), baseline-контекст пересобирается с бюджетом дня 28 без повторного реранка; метрики: заземление/стабильность (скоринг дня 28), p50, ток/с, длина ответа, prompt-токены (кэш-прогоны исключены), RAM модели (GET /api/ps), холодный старт; артефакт `data/rag/tune-local.json` + режим `--report` |
| Дисциплина памяти | модели грузятся по одной (выгрузка `keep_alive: 0` между фазами A/B), RAM каждой — из `/api/ps` |
| Прод | тот же код (деплой 10.10): 0.5b — профиль {2048, 1000} без роста RAM VPS + темп 0.2 и RAG-промпт; прод-смок: ответ по карточке, ₽0, потолок num_predict сработал как защита от рамблинга слабой модели |

## Быстрый старт

```bash
npm install                # воркспейсы: shared + server + client
npm run build              # shared → server → client (SPA собирается последней)

# локальная ветка: Ollama + модель каталога
ollama pull qwen2.5:1.5b

cd server
npm run dev                # API на :3000 (DEEPSEEK_API_KEY в server/.env — для облачной ветки)
npm run local-llm:check -- --rag      # wiring локального RAG-хода (бюджет профиля модели)
npm run local-llm:tune                # A/B до/после/квант: 8 вопросов × 2 прогона × 3 арма
npm run local-llm:tune -- --report    # таблица из артефакта без пересчёта

# SPA — второй терминал из корня репо
npm run dev:spa            # vite :5173, /api проксируется
```

# AI Advent Challenge #9 — Week 06, Day 28

**Trigger Helper** — продуктовый SPA самопомощи по триггерным точкам (Svelte 5 + Fastify). День 28 замыкает локальный контур: **RAG-пайплайн работает полностью локально** — retrieval (эмбеддинги E5 + кросс-энкодер реранк, без облака, ₽0) и генерация ответа локальной моделью (Ollama) в обычном чате. Плюс скрипт честного сравнения «локальная vs облачная»: качество / скорость / стабильность на одних вопросах. Живое демо: https://trigger.ksvitkov.ru

## Demo на видео

1. **Чат A — два локальных RAG-хода (Qwen2.5 1.5B)**: вопрос по базе → живой прогресс поиска («Ищу по базе… N с», фаза реранка, тикер ⏱ в заголовке хода) → генерация «● N ток» → ответ с опорой на retrieved-карточки, чип «локальная · RAG · Источники N», каждый ход ₽0.00. Второй вопрос («как массировать») — по той же карточке с историей первого хода.
2. **Чат B — те же два вопроса на облачной (дефолт free deepseek)**: развёрнутые ответы с чипом «Источники N · цитаты M/K».
3. **Сравнение переключением чатов** (~10 с на чат) — обе ленты с одними и теми же двумя вопросами в кадре.
4. **Терминал: `npm run rag:compare -- --report`** — таблица сравнения с легендой колонок: успех, латентность генерации, ток/с, заземление, стабильность (8 контрольных вопросов × 2 арма × 2 прогона).

## Выводы

*(дословно автора)*

Использование локальной ллм для полного цикла существенно повышает время ответа (слабое железо сервера). При этом приходится сильно ограничивать ее в свободе, чтобы уменьшить вероятность галлюцинаций (маленькая модель). Ошибки, в том числе, грамматические, конечно, все равно вероятны. Можно было бы обвесить дополнительно проверкой орфографии и сделать еще один проход, повышающий качество текста. Ну и модель, конечно, надо посильнее для того, чтобы адекватно отвечать на запросы. Тем не менее, с нормальным корпусом данных и поиском по базе даже такая маленькая модель справляется удовлетворительно.

## Что где реализовано

| Пункт задания | Где |
|:---|:---|
| Локальная LLM подключена к RAG-пайплайну | `server/src/routes/chat.ts` — локальная ветка при `preset:"rag_chat"` делает детерминированный retrieval до генерации (0.5b/1.5b tool-loop не водит — поиск серверный, без LLM-оркестрации) |
| Индекс используется; retrieval локально | `server/src/services/local-llm.ts` — `localRagRetrieve`: `rankByQueries` (без rewrite — облачный шаг) → dontKnow-гейт (косинус top-1 против коммиченного `data/rag/tune-dontknow.json`) → реранк (порог из `tune-rerank.json`) → контекст ≤~1000 ток / k≤6 (локальный бюджет под `num_ctx 2048`; облачные 3k/16 не переиспользованы) |
| Генерация — через локальную модель | retrieved-контекст уходит в промпт SEC-F3-блоком (`buildContextDataBlock`), `LocalLlmChatParams.context`; история диалога дня 27 сохранена |
| dontKnow-гейт локально | ниже порога — canned «не знаю» ₽0 без вызова модели (`localDontKnowAnswer`) |
| Сравнение локальная vs облачная | `server/src/scripts/compare-local-rag.ts` + `npm run rag:compare`: retrieval один на вопрос → два генератора (1.5b локально / deepseek-chat бесплатно), 2 прогона, детект заглушек day25-класса с 1 ретраем; артефакт `data/rag/compare-local.json` |
| Оценка: качество/скорость/стабильность | метрики артефакта: успех, p50/mean латентность, ток/с, заземление (метки источников в ответе через `normalizeRu`), стабильность (2/2 одинаковый вердикт) |
| Evidence в UI | трейс несёт rag-payload той же формы, что облако (чип «Источники»); чип `ModelChip` — « · RAG» вместо « · без RAG»; прогресс-ключ `local-rag` («Ищу по базе…») в titleMap |
| Wiring-проверка | `npm run local-llm:check -- --rag` — PASS = непустой ответ и рост prompt_tokens против хода без контекста |

## Быстрый старт

```bash
npm install                # воркспейсы: shared + server + client
npm run build              # shared → server → client (SPA собирается последней)

# локальная ветка: Ollama + модель каталога (0.5b — слабые хосты, 1.5b — по RAM)
ollama pull qwen2.5:1.5b

cd server
npm run dev                # API на :3000 (DEEPSEEK_API_KEY / ProxyAPI в server/.env — для облачной ветки и сравнения)
npm run local-llm:check -- --rag      # wiring локального RAG-хода
npm run rag:compare                   # сравнение локальная vs облачная (8 вопросов × 2 прогона)

# SPA — второй терминал из корня репо
npm run dev:spa            # vite :5173, /api проксируется
```

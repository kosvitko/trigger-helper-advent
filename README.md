# AI Advent Challenge #9 — Week 03, Day 12

**Задание:** добавить персонализацию поверх модели памяти: профиль пользователя (предпочтения — стиль, формат, ограничения), подключённый к каждому запросу; проверить ответы для разных профилей и что ассистент учитывает их автоматически. Несколько профилей и профиль-роутер допустимы. Сдача: видео + код.

Trigger Helper (day12): профили пользователей уровня инстанса — `profiles[]` + `activeProfileId` (ручной роутер, ровно как «выбрать конкретный профиль» из уточнения задания). При первом обращении инстанс получает два seed-профиля-контраста («Кратко и по делу»: только маркированные списки ≤5 пунктов / «Тепло и развёрнуто»: 2–3 связных абзаца). Активный профиль на **каждом** запросе **каждого** агента инжектится отдельным system-сообщением после базовых инструкций (позже = весомее) с явной мета-строкой приоритета: профиль главнее стиля пресета при конфликте, но не отменяет тему самопомощи и дисклеймер. Профили хранятся отдельно от фактов памяти day11 (своя секция снапшота, свой store); классификатор памяти и сжатие профиля не видят. Деактивация («— без профиля —») возвращает поведение day11.

## Demo на видео (~47s)

Один и тот же вопрос — «Шея затекла после долгого дня за компьютером — что делать?» — в трёх свежих тредах; Lab: `История = tail·10`, автосжатие выключено:

| | |
|:--|:--|
| **Seed** | новый инстанс — панель «Профиль (day12)» сразу показывает два профиля-контраста с полями Название / Стиль / Формат / Запреты |
| **Профиль → списки** | активация «Кратко и по делу»; ответ — маркированный список, у сообщения бейдж профиля, в payload виден inject-блок «## Профиль пользователя» |
| **Свежий тред, другой профиль** | новый агент (чистый тред — классификатор памяти не подмешивает формулировки), активация «Тепло и развёрнуто»; тот же вопрос — 2–3 абзаца без списков |
| **Деактивация** | «— без профиля —»; третий свежий агент отвечает в дефолтном стиле пресета, бейджа нет, профиля в payload нет — контраст доказывает автоматический учёт |

## Выводы

- **Профиль — это роутер над формой ответа, память — над содержанием.** Развязка «профиль = как отвечать, память = что помнить» устранила конфликт позиций в промпте: профиль идёт сразу после пресета и раньше памяти, а мета-строка явно отдаёт ему приоритет по стилю — память при этом остаётся фактами, а не указаниями.
- **Контраст формата надёжнее контраста тона.** «Обращение по имени» на видео не доказать (имени в контексте нет), а «списки ≤5 vs связные абзацы» различимо в кадре без комментариев — seed-профили сделаны структурными.
- **Автоматичность = inject на уровне роутов, а не инструкции модели.** Активный профиль резолвится серверно на каждом `run` всех агентов (клиент не может его подменить), поэтому «учитывает автоматически» — свойство системы, а не послушание LLM.
- **Хранение раздельно — дёшево, если делать additive.** Отдельный store + отдельная секция снапшота + per-key валидация записей при загрузке: старые state-файлы поднимаются без миграций, битая запись профиля отбрасывается с warning, не роняя файл.

## Что где реализовано

| Требование | Где |
|:-----------|:----|
| Профиль пользователя (стиль/формат/ограничения) | `shared/src/schemas/agent.ts` — `UserProfile` (капы: label ≤120, style/format ≤200, constraints ≤5×80) |
| Несколько профилей + роутер | `server/src/services/agent/profile-state.ts` — `ProfileStateStore`: `profiles[]` + `activeProfileId`, `activate(profileId\|null)`, seed 2 контрастов |
| Подключён к каждому запросу | `server/src/routes/agents.ts` — резолюция `getActiveProfile()` в `run` всех агентов; CRUD+activate: `GET/POST/PATCH/DELETE …/profiles`, `POST …/profiles/activate` |
| Автоматический учёт | `server/src/services/agent/llm-agent.ts` — `buildProfileMessage()` (мета-строка приоритета), inject после preset до памяти; `context.profile` + бейдж в UI |
| Раздельное хранение | секция `profiles` в `var/agent-state.json` (per-key safeParse + warning), отдельный `ProfileStateStore`; память day11 не тронута |
| Проверка разных профилей | панель «Профиль (day12)» в правом доке (селектор, поля, instant-PATCH, 409 на удаление активного), видео-контраст трёх ответов |

## Demo через API

```bash
# инстанс + агент (пресет care); при первом GET профилей — сид 2 контрастов
curl -X POST http://127.0.0.1:3000/api/instances -H "Content-Type: application/json" -d '{"seedPresetIds":["care"]}'
curl http://127.0.0.1:3000/api/instances/<iid>/profiles

# активировать профиль (роутер ручной; null = деактивация)
curl -X POST http://127.0.0.1:3000/api/instances/<iid>/profiles/activate -H "Content-Type: application/json" \
  -d '{"profileId":"<pid>"}'

# правка предпочтений (пустая строка = очистить; constraints — массив, строка = запрет)
curl -X PATCH http://127.0.0.1:3000/api/instances/<iid>/profiles/<pid> -H "Content-Type: application/json" \
  -d '{"format":"Только списки, максимум 5 пунктов","constraints":["Не предлагать растяжку"]}'

# ход агента — профиль применён ко всем агентам инстанса: context.profile.inject в ответе
curl -X POST http://127.0.0.1:3000/api/instances/<iid>/agents/<aid>/run -H "Content-Type: application/json" \
  -d '{"input":"Шея затекла после долгого дня за компьютером — что делать?"}'

# удаление активного профиля — 409 (сначала деактивировать)
curl -X DELETE http://127.0.0.1:3000/api/instances/<iid>/profiles/<pid>
```

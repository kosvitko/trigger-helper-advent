# AI Advent Challenge #9 — Week 04, Day 19

**Задание:** создать несколько MCP-инструментов (например: search; summarize; saveToFile). Реализовать пайплайн: первый инструмент получает данные, второй — обрабатывает, третий — сохраняет результат. Проверить автоматическое выполнение цепочки и корректность передачи данных между инструментами. Результат: автоматический пайплайн из нескольких MCP-инструментов. Сдача: видео + код.

Trigger Helper (day19): **автопостроение пайплайна агентом** — один промпт-цель, агент сам ведёт цепочку из трёх инструментов своего MCP-сервера в **мульти-раундовом tool-loop** (день 17 снимал однораундовое ограничение — теперь каждый раунд с инструментами, данные передаются между тулзами через результаты в аргументах следующего вызова). Три новых инструмента (итого 9): **`search`** — публикации PubMed без API-ключей (компактные метаданные, окно 30 дней, ₽0); **`summarize`** — сводка по `pmid` из search (абстракты дофетчивает сама тулза; внутри — вложенный вызов `deepseek-chat` с бюджет-гардой 0.95× и записью в ledger); **`saveToFile`** — первый пишущий инструмент: whitelist имени, жёсткий корень `var/pipelines/`, контент ≤64 КБ, ротация ≤20 файлов, атомарная запись tmp+rename. Капы: ≤4 раундов, ≤8 вызовов тулз за ран; пропущенные по капу вызовы получают синтезированный ответ (парность tool_call↔tool-message), при исчерпании капа — финальный ответ без инструментов (деградация = поведение day17). **Стадии цепочки видны в чате** во время выполнения: на каждый вызов тулзы в ленту падает сообщение «⚙️ пайплайн» («🔎 Ищу публикации…» → «✍️ Готовлю сводку…» → «💾 Сохраняю файл…») — UI-only, в LLM-контекст не попадает. Попутно: публичный DeepWiki MCP убран из демо — остался только свой сервер; список моделей без сильной (решение по стоимости: ран на дефолтном DeepSeek — ₽0.21). Ноль новых npm-зависимостей.

## Выводы

Для использования автопостроения пайплайнов в дешевых моделях тулзам требуется достаточно подробное описание. Дорогие модели могут собирать пайплайн с меньшим количеством хинтов.

## Что где реализовано

| Требование | Где |
|:-----------|:----|
| Несколько MCP-инструментов | `server/src/services/mcp-server.ts` — +3 `registerTool` (схемы Zod + JSON Schema — рядом, в конце `OWN_MCP_TOOL_SCHEMAS`) |
| Инструмент «получает данные» | `services/pubmed.ts` — PubMed E-utilities без ключей (esearch 30-дн окно → esummary: pmid/название/журнал/авторы, без абстрактов) |
| Инструмент «обрабатывает» | `summarize({pmids≤5})` — сама тулза дофетчивает абстракты (≤4000 симв каждый) и вызывает `deepseek-chat` (500 ток, 60 с); бюджет-гарда 0.95× + `ledger.record` — вложенный вызов учтён отдельно |
| Инструмент «сохраняет» | `saveToFile({filename, content})` — whitelist `[A-Za-z0-9._-]` + `.md/.txt`, `var/pipelines/` (env `PIPELINES_DIR`), ≤64 КБ, ротация ≤20, атомарная запись tmp+rename в сериализованной цепочке |
| Автоматическая цепочка | мульти-раунд в `services/agent/llm-agent.ts`: раунды с инструментами до результата, кап 4 раунда / 8 вызовов, анти-дубликат, при исчерпании — финальный ответ без tools |
| Передача данных | pmid из `search` → аргументы `summarize`; текст сводки → `content` в `saveToFile` (через tool-результаты в контексте рана) |
| Стадии в чате | `run(onStage)` → system-сообщения «⚙️ пайплайн» в тред рана; из LLM-контекста исключены (фильтр по label) |
| Сохранённые файлы | `GET /api/pipelines` (список + `?name=`) + секция «Пайплайны» в блоке «MCP» |

## Demo через API

```bash
# шаг 1: поиск публикаций (PubMed без ключей)
curl -X POST http://127.0.0.1:3000/api/mcp/call -H "content-type: application/json" \
  -d '{"name":"search","arguments":{"query":"massage therapy","retmax":3}}'

# шаг 2: сводка по найденным (pmid из search; внутри — вложенный вызов LLM)
curl -X POST http://127.0.0.1:3000/api/mcp/call -H "content-type: application/json" \
  -d '{"name":"summarize","arguments":{"pmids":["42709539","42703097"]}}'

# шаг 3: сохранение сводки в файл
curl -X POST http://127.0.0.1:3000/api/mcp/call -H "content-type: application/json" \
  -d '{"name":"saveToFile","arguments":{"filename":"pubmed_summary.md","content":"# Сводка…"}}'

# сохранённые файлы (он же финальный кадр видео)
curl http://127.0.0.1:3000/api/pipelines
curl "http://127.0.0.1:3000/api/pipelines?name=pubmed_summary.md"
```

А на камере — вся цепочка одним вопросом агенту (мульти-раунд сам передаёт данные между тулзами):

```bash
curl -X POST http://127.0.0.1:3000/api/agent/run -H "content-type: application/json" \
  -d '{"instanceId":"…","agentId":"…","input":"Сохрани саммари по свежим статьям PubMed о массаже в файл","overrides":{"tools":true}}'
```

# AI Advent Challenge #9 — Week 05, Day 25

**Trigger Helper** — мини-чат с RAG-агентом и памятью задачи в продуктовом SPA (Svelte 5 + Fastify + DeepSeek): история диалога, при каждом вопросе — поиск по базе, ответы с обязательными источниками, честное «не знаю», и живой трейс всех шагов агента рядом с диалогом. Живое демо: http://91.188.212.10.

## Demo на видео (~1:50 + таймлапс ~2:00)

Всё — в продуктовом UI:

1. **Вопрос по зоне боли → ответ бытовым языком** — «куда ставить палец, что почувствуешь, сколько держать», с чипом источников и верифицированными цитатами.
2. **Трейс всех шагов хода** наполняется в реальном времени (SSE): классификация памяти → rag_ask → рерайт запроса → поиск по базе (косинус/порог) → черновик по базе → верификация цитат → нарратив → рельса-чек → память задачи. Клик по ходу или баблу синхронно выравнивает обе колонки.
3. **Память задачи** (цель/уточнено/ограничения) — пополняется из диалога, редактируется, переживает перезагрузку.
4. **Таймлапс** — 12 ходов подряд (уточнения → ограничение → техники → off-corpus вопрос → возврат к теме): цель жива к последнему сообщению, источники в каждом ответе, финал — «рельса источников 12/12 · нарушений 0».

## Выводы

1. В разработке АИ-приложения важная часть (как и в любом ML... да и в любой аналитике... возможно, в любом приложении ;))) - отладочная среда. Соответственно, встраивание отладки (трейсов в данном случае) в приложение существенно повышает возможности для отладки поведения агента.
2. сама по себе задача создания законченного приложения поднимает различные вопросы, в т.ч. юридического характера - приходится прорабатывать комплексно.
3. Непосредственно RAG и работа с источниками: сильная привязка к источникам очень влияет на тон, для более-менее адекватного диалога его нужно тюнить.
4. Память задачи - отлично ложится в общую концепцию со своей маленькой моделью (мелким промптом) впереди. Важным оказалось передавать в модель уже существующие факты, чтобы уменьшить дупликацию.
5. Формулирование нескольких вариантов вопроса для запроса RAG из краткого вопроса пользователя очень облегчает поиск.
6. Работа в приятном интерфейсе приятнее ;)))

В целом, впереди здоровенная волна рефакторинга по результатам ревью и анализа именно "product-like" версии приложения, при том, что бэк в принципе не очень менялся. Но зато полезли дефекты, которые оказывали существенное влияние на вывод агента.

## Что где реализовано

| Пункт задания | Где |
|:---|:---|
| Мини-чат хранит историю диалога | `server/src/services/agent/threads.ts` — персист-треды; SPA восстанавливает ленту при входе (GET messages) |
| Контекст из базы при каждом новом вопросе | локальная тулза `rag_ask` в tool-loop агента (`services/agent/rag-tool.ts`): rewrite вариантов запроса → поиск (косинус, dontKnow-гейт) → ответ+цитаты (jsonMode) → серверная верификация |
| Ответы с источниками | жёсткая рельса «RAG каждый ход + метки [source › section]» в run-пайплайне (`routes/agents.ts`): нарушение → один re-prompt → честный `meta.railViolated`; UI — чип «Источники N · цитаты M/M ✓» |
| Память задачи | `services/agent/chat-task-state.ts` — {goal, clarified, constraints_terms}, экстракт малой моделью каждый ход (с показом уже известного — без дублей-парафразов), инжект в промпт, панель в UI (GET/PATCH) |
| Веб-UI | `client/` — Svelte 5 SPA: диалог + трейс (SSE, шаги пайплайна живьём), память задачи, настройки (модель/контекст/поиск/тема) |
| Проверка на 2 длинных сценариях | `server/src/scripts/eval-rag-chat.ts` — 2×12 сообщений: 22/24 хода fully green, **aliveAt15 = true в обоих** (цель и ограничения живы к сообщению 15), рельса 2/24 — формат-фолбэк провайдера (документированный стохастический класс) |

## Быстрый старт

```bash
npm install            # воркспейсы: shared + server + client
npm run build          # shared → server → client (SPA собирается последней)
cd server && npm run dev   # API на :3000 (ключ: DEEPSEEK_API_KEY в server/.env)
# SPA: npm run dev:spa — второй терминал (vite :5173, /api проксируется)

# длинные сценарии 2×12 (сервер остановить: ledger — единый писатель)
npm run rag:eval-chat  # → data/rag/eval-chat.json
```

## Demo через API

```bash
# создать сессию RAG-чата и задать вопрос
curl -X POST http://127.0.0.1:3000/api/instances \
  -H "Content-Type: application/json" \
  -d '{"label":"demo","seedPresetIds":["rag_chat"]}'
curl -X POST http://127.0.0.1:3000/api/agent/run \
  -H "Content-Type: application/json" \
  -d '{"instanceId":"…","agentId":"…","input":"болит голова, что делать?","overrides":{"tools":true}}'
# → { reply, message, context.tool.calls[rag_ask]{sources,quotes,topCosine,…},
#     context.chatTaskState{goal,clarified,…}, meta.railViolated:false }

# off-corpus — честное «не знаю» (вопрос вшит в отказ)
curl -X POST http://127.0.0.1:3000/api/agent/run … -d '{"input":"как продлить визу в Таиланде?",…}'
# → dontKnow=true, источников нет, бюджет ответа ₽0
```

Деградация (дизайн-контракт): сбой экстракта памяти — fail-open (состояние не меняется); сбой формата rag-ответа — fallback-цитаты сервера; длинные ходы — SSE-keepalive (прокси не рвёт поток); дневной бюджет — 429.
